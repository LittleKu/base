# Chromium base

[简体中文](README.zh-CN.md)

## Features

Use Chromium's `base` library in standalone C++ projects for logging, files, strings, JSON, time, thread pools, and asynchronous tasks. Source and dependency revisions are managed in [DEPS](DEPS).

- Automatically sync the pinned Chromium sources and dependencies, with a static `base` build by default.
- Build with GN / Ninja and generate Visual Studio projects.
- Explore the [example](examples/example.cc) logging sample and [base_smoke_test](examples/base_smoke_test.cc), which checks file operations, JSON, thread pools, and related functionality.

## Usage

### Windows

#### Prerequisites

These instructions target Windows x64 and use a locally installed Visual Studio toolchain.

1. Install [Git for Windows](https://git-scm.com/install/windows) and make sure `git` is available on the command line.
2. Install [Visual Studio 2026](https://visualstudio.microsoft.com/downloads/) with **Desktop development with C++**, the x64/x86 build tools, and the matching **C++ ATL** component. Also install **MSVC v143 - VS 2022 C++ x64/x86 build tools** to load the v143 projects generated by GN below.
3. Install [Windows SDK 10.0.28000.2526](https://learn.microsoft.com/en-us/windows/apps/windows-sdk/downloads), including **Debugging Tools for Windows**. Its SDK version directory is `10.0.28000.0`, matching the current build configuration.
4. Ensure network access to GitHub and Chromium's source and dependency download services. Choose a short workspace path without spaces.

The steps below install Python managed by `depot_tools` and sync GN, Ninja, Clang, and the Rust toolchain.

Run all commands in order in **the same CMD (`cmd.exe`) window**, continuing only after each step succeeds. The example uses a new `X:\chromium-base` directory; adjust the path as needed.

#### 1. Create the workspace

```bat
mkdir X:\chromium-base
cd /d X:\chromium-base
git config --global core.longpaths true

mkdir work\temp work\vpython
set "TEMP=%CD%\work\temp"
set "TMP=%TEMP%"
set "TMPDIR=%TEMP%"
set "VPYTHON_VIRTUALENV_ROOT=%CD%\work\vpython"
set "CIPD_CACHE_DIR=%CD%\cipd_cache"
```

#### 2. Install and pin depot_tools

```bat
git clone https://chromium.googlesource.com/chromium/tools/depot_tools.git depot_tools
git -C depot_tools checkout b86fc981b72ab966f8260f73b4eca600b3b12677

set "DEPOT_TOOLS_UPDATE=0"
set "DEPOT_TOOLS_WIN_TOOLCHAIN=0"
set "PATH=%CD%\depot_tools;%PATH%"
call depot_tools\bootstrap\win_tools.bat
```

With automatic updates disabled for the pinned version, the last command explicitly initializes Python and the other Windows tools.

#### 3. Fetch the repository, sources, and dependencies

```bat
call gclient config --unmanaged --name=src --cache-dir "%CD%\git_cache" https://github.com/LittleKu/base.git
call vpython3 depot_tools\gsutil.py version
call gclient sync --no-history
cd src
```

`gclient sync` creates `src`, invokes the source sync script for the pinned Chromium revision, and installs the required dependencies. There is no separate repository clone or manual source sync step.

#### 4. Generate the sample projects

```bat
buildtools\win\gn.exe gen out\Debug ^
  --ide=vs2022 ^
  --sln=base ^
  --filters=//examples:* ^
  --winsdk=10.0.28000.0 ^
  --ninja-executable="%CD%\third_party\ninja\ninja.exe" ^
  --args="is_debug=true use_siso=false use_remoteexec=false"
```

The generated `out\Debug\base.sln` contains `example`, `base_smoke_test`, and their dependencies. The pinned GN generates projects in `vs2022` format; builds use Ninja and the synced Clang toolchain.

#### 5. Build, run, and open the solution

```bat
third_party\ninja\ninja.exe -C out\Debug default
out\Debug\base_smoke_test.exe
start /wait "" out\Debug\example.exe
type out\Debug\example.log
start "" out\Debug\base.sln
```

The smoke test prints `base smoke test passed` on success. The logging example writes to `example.log` and exits. Set `example` as the startup project in Visual Studio to debug it.

When opening a new terminal, return to `X:\chromium-base`, restore the environment variables from steps 1 and 2, then run `cd src`. Launch Visual Studio from that terminal so it inherits the build environment.
